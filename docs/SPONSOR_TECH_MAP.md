# Sponsor technology map

PayGuard AI is the earlier name of TradeGlot; receipt files and some screenshots under `docs/evidence/` keep the old name.

One page that answers "what is actually used, where, and is it live on the hosted demo?". Statuses: **Hosted** = a judge can use it on the public demo (synthetic data); **Recorded** = the hosted demo replays a saved real run, no live call; **Local only** = works only on a local console with the owner's key; **Not used** = stated so nobody has to look. Versions are the ones in `frontend/package.json` and `render.yaml`.

One-picture version: `docs/submission/diagrams/sponsor_evidence.png` (what ran for each sponsor, with the evidence file named on each card).

The hosted demo's PayPal calls are Sandbox reads (OAuth token, list disputes, read one dispute) and, with its send opt-in, one capped evidence send (once per dispute and per visit, at most 2 sends per address per day, 3 per 10 minutes and 15 a day; one such send was made on 2026-11-10, see `docs/evidence/RECEIPT_20261110_hosted_live.md`); every other write route answers 503. It uses the author's own Sandbox test credentials stored as Render secrets and holds no Channel3 key. It shows the author's own Sandbox test disputes; the list shows each id as a masked code (the first deployment returned full test ids; the masked version was checked live after commit d10c0ed, see `docs/evidence/HOSTED_READONLY_LIVE_20261109.md`); an opened case carries its Sandbox transaction id (test data). Its evidence guide uses keyword rules unless the operator opts in to Gemini (free-tier key, 5 calls a minute and 20 a day shared by all visitors; past that it falls back to keywords); the evidence brief and the Studio agents never run there, and the dashboard replays one recorded Studio run. Every real write above is backed by a receipt or a recording. The numbers on the other pages can be rechecked with `tools/verify_public_numbers.py`.
