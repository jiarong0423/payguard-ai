# Security Boundary

Baseline review date: 2026-10-04. Latest contract review: 2026-10-08. Owner: main architect. Scope: local synthetic console plus optional PayPal Sandbox adapter.

Backend route/auth/data controls are specified in docs/decisions/2026Q4/console_contract.md. Loopback binding, exact Origin/Host allowlists, session-bound CSRF, memory TTL and row/rate/body bounds are required. No public deployment or real merchant authentication is claimed.

Secret owner: the local operator owns PAYPAL_CLIENT_ID and PAYPAL_CLIENT_SECRET. Storage: backend process environment only; agents must not inspect values or read .env files. Rotation: replace Sandbox app credentials through the PayPal developer dashboard, restart the backend to invalidate cached access, and verify only the sanitized connection status. Revoke: disable the Sandbox app credentials through the provider and stop the local adapter. No secrets or upstream payloads enter logs, receipts, browser state or exports.

HMAC identifiers are pseudonymization. Local review is not durable authenticated authorization. No invoice send, payment, refund or production dispute submission is enabled. The bounded AI path is disabled by default. The Python 3.13 API imports no provider SDK; a dedicated Python 3.12 worker owns `google-genai==2.28.0` and may send only server-authored synthetic facts and pinned citation IDs to Vertex API `v1`, location `global`, model `gemini-3.8-flash`. It accepts no raw PII, merchant/session payload, arbitrary prompt, tool call or financial action. The server-owned `payguard-bounded-advisory-v2` prompt contract treats all input as data, disables tools and automatic function calling, and constrains every generated sentence to a stage-specific enum. The backend permanently reserves a maximum of three model attempts per process, one per fixed stage, before provider execution. Failed, timed-out, cancelled and invalid-response attempts consume their slot; no automatic retry occurs. Session reset, expiry or replacement cannot restore a slot. Process restart and multiple workers can still create new local budgets, so any public multi-instance deployment requires a durable shared atomic quota and an API-gateway cost circuit breaker before outbound AI is enabled. The accepted receipt proves one observed invocation only; mock transport results and the receipt cannot establish repeatability, real-record safety, policy correctness or production readiness.

The optional LM Studio profile is a separate default-off loopback transport. It is fixed to `127.0.0.1:1234` and `nvidia-nemotron-3-nano-4b`, uses `httpx` with environment proxy inheritance and redirects disabled, sends no authentication header, accepts no endpoint or model override, serializes inference, requests no reasoning, exposes no tools and never falls back to Gemini. Nonempty reasoning, tool calls, model drift, extra generated fields, free text, reordered citations and invalid authority fields fail closed. Starting the local profile does not authorize network exposure; LM Studio must keep local-network serving disabled.

## Public upload credential prohibition

Repository content, release packages, browser bundles, screenshots, logs and AI prompts must contain no credential value, access token, provider project identity, account identifier or `.env` payload. Configuration names may be documented only as names. Operator credentials remain outside Git in the backend process environment or an approved deployment secret manager. Public packaging must run the exact secret, history and export gates against the candidate bytes; a passing scan does not authorize publication.

Threat model: docs/decisions/2026Q4/threat_model.md. Package review and locked dependency evidence are recorded in the console work-order manifest. The exact current release repository has bounded SAST, dependency, secret, history, rights/notices, public-export and anonymous-repository-readback evidence. Public source publication is complete. Only video publication and Devpost submission remain in the competition submission path. Deployment approval remains open; this evidence does not authorize public or production hosting, production PayPal authority, real PII, shared quotas or local-model distribution.
