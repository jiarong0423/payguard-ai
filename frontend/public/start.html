Try the hosted demo with curl

A session needs an Origin header equal to the site; every call then sends X-Demo-Session, and every POST also X-CSRF-Token. Connect first, otherwise the dispute list shows labelled fixtures (its note says so).

H=https://payguard-demo-j2b3.onrender.com
curl -s -X POST $H/api/v1/demo/sessions -H "Origin: $H" -H 'Content-Type: application/json' -d '{}'   # 201: session_id, csrf_token
# S=<session_id>  C=<csrf_token> from that answer
curl -s -X POST $H/api/v1/paypal/connect -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{}'   # 200 connected (Sandbox reads; a send also needs the review and the two-step send dialog)
curl -s $H/api/v1/paypal/disputes -H "X-Demo-Session: $S"   # 200, source paypal_sandbox, masked ids
curl -s -X POST $H/api/v1/demo/inject -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{"scenario":"dispute"}'   # 200: loads the synthetic cases case-ref-001 to 003 (without it the next call answers 404 case_not_found)
curl -s -X POST $H/api/v1/disputes/case-ref-001/draft -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{}'   # 200: evidence draft, READY_FOR_LOCAL_REVIEW, nothing sent
curl -s -X POST $H/api/v1/paypal/invoices/draft -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{}'   # 503 hosted_demo_disabled
