Start here: try TradeGlot in about five minutes

TradeGlot checks a sale before you ship, then helps a seller prepare dispute evidence and send it to PayPal Sandbox only after a person approves. Verified on 2026-11-10: a send from this hosted site, PayPal-Debug-Id f869050ae2a63 (masked receipt in the repository).

Open the demo and press “Run the step 1 example”

The free server can take up to a minute to wake up on the first visit.

The five-minute path

  1. 1Check a sale hostedPress Run the step 1 example. An item matching a listed Singapore restriction triggers a rule match and pauses the draft, with the rule and its official source.
  2. 2Dispute evidence hostedSelect Dispute evidence (03) in the top stepper, pick a case, press Prepare evidence draft. Expect “Ready for human review” and a review ZIP. Below it, the recorded replay sends nothing. The PayPal Sandbox disputes block lists the author’s Sandbox test disputes; on the hosted site it is usually already connected, and its Connect US Sandbox button shows only when it is not. When the send switch is on, you can send that evidence to one of them instead.
  3. 3AG Studio evidence dashboard hosted recorded agent runAsk “Which reason code appears most often across the three cases?” The answer replays a real Gemini run, labelled as recorded.
  4. 4Proof and receipts recordedWhat was shown, how, when, and from which file, including the recorded real send to the PayPal Sandbox.
  5. 5Scenario runs hostedFixed scenarios you can rerun to see the same result.

Times on screen: a time marked UTC is UTC (as on the AG Studio dashboard, the Evidence deadline board, the Time evidence block and Technical details); every other time in the console, including the PayPal Sandbox dispute list, is shown in your own time zone with its name (for example GMT+8).

What is real, what is recorded

The hosted site reads the author’s own Sandbox test disputes (ids shown as masked codes) and, with the send switch on, one capped evidence send per visit to the author’s own Sandbox test disputes (at most 2 sends per address per day, 3 per 10 minutes and 15 a day for all visitors); invoice drafts, tracking, webhooks, the AI brief and the Studio agents are switched off on the hosted site.

When none is waiting for the seller, the page opens the recorded replay. Six PayPal Sandbox evidence sends are shown as receipts and notes: five made on the author’s computer and one made from this hosted site on 2026-11-10.

AG Studio’s built-in agents ran live on the local console on 2026-11-04 (several runs, none saved), on 2026-11-08 (one run, recorded) and on 2026-11-09 (three runs, 11 tool calls, recorded); the hosted dashboard replays the recording dated 2026-11-09, with its four questions, and calls no model. Ten Channel3 searches were real too (five of them are replayed here). The data is synthetic and PayPal decides every real dispute.

Three claims, in plain text

  • Rules flag, a person approves: an item matching a listed Singapore restriction triggers a rule match and pauses the draft, with the rule and its official source; the policy check itself sends nothing to PayPal.
  • The hosted site uses a PayPal Sandbox test account only: Sandbox reads with masked dispute ids and, with the send switch on, one capped evidence send per visit to the author’s own Sandbox test disputes (at most 2 sends per address per day, 3 per 10 minutes and 15 a day for all visitors); every other write route is switched off (code hosted_demo_disabled).
  • Every claim has a row on the proof page (also readable without JavaScript in docs/evidence). Machine-readable: /api/v1/openapi.json and /llms.txt.

Try the API with curl

A session needs an Origin header equal to the site; every call then sends X-Demo-Session, and every POST also X-CSRF-Token. Connect first, otherwise the dispute list shows labelled fixtures (its note says so).

H=https://payguard-demo-j2b3.onrender.com
curl -s -X POST $H/api/v1/demo/sessions -H "Origin: $H" -H 'Content-Type: application/json' -d '{}'   # 201: session_id, csrf_token
# S=<session_id>  C=<csrf_token> from that answer
curl -s -X POST $H/api/v1/paypal/connect -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{}'   # 200 connected (Sandbox reads; a send also needs the review and the two-step send dialog)
curl -s $H/api/v1/paypal/disputes -H "X-Demo-Session: $S"   # 200, source paypal_sandbox, masked ids
curl -s -X POST $H/api/v1/paypal/invoices/draft -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{}'   # 503 hosted_demo_disabled

Prefer your own computer?

A click-through package (11 MB zip, public source plus the built console, no keys) runs the same demo locally; the send step is the same recorded replay. It needs Python 3.13 and uv; RUN_FIRST.txt inside has the one command. To check our numbers yourself, run tools/verify_public_numbers.py there: it re-counts the figures on the pages and marks the one run-time-only count (the stress-test requests) MANUAL.
