What is real, what is recorded

The hosted site reads the author’s own Sandbox test disputes (ids shown as masked codes) and, with the send switch on, one capped evidence send per visit to the author’s own Sandbox test disputes (at most 2 sends per address per day, 3 per 10 minutes and 15 a day for all visitors); invoice drafts, tracking, webhooks, the AI brief and the Studio agents answer 503. Six PayPal Sandbox evidence sends are shown as receipts and notes: five made on the author’s computer and one made from this hosted site on 2026-11-10. One AG Studio agent run and ten Channel3 searches were real too (five of the searches are replayed here). The data is synthetic and PayPal decides every real dispute.

Three claims, in plain text

  • Rules decide, a person approves: a banned product to Singapore is stopped with the rule and its official source; the policy check itself sends nothing to PayPal.
  • The hosted site uses a PayPal Sandbox test account only: Sandbox reads with masked dispute ids and, with the send switch on, one capped evidence send per visit to the author’s own Sandbox test disputes (at most 2 sends per address per day, 3 per 10 minutes and 15 a day for all visitors); every other write route answers 503 hosted_demo_disabled.
  • Every claim has a row on the proof page (also readable without JavaScript in docs/evidence). Machine-readable: /api/v1/openapi.json and /llms.txt.

Try the API with curl

A session needs an Origin header equal to the site; every call then sends X-Demo-Session, and every POST also X-CSRF-Token. Connect first, otherwise the dispute list shows labelled fixtures (its note says so).

H=https://payguard-demo-j2b3.onrender.com
curl -s -X POST $H/api/v1/demo/sessions -H "Origin: $H" -H 'Content-Type: application/json' -d '{}'   # 201: session_id, csrf_token
# S=<session_id>  C=<csrf_token> from that answer
curl -s -X POST $H/api/v1/paypal/connect -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{}'   # 200 connected, read-only
curl -s $H/api/v1/paypal/disputes -H "X-Demo-Session: $S"   # 200, source paypal_sandbox, masked ids
curl -s -X POST $H/api/v1/paypal/invoices/draft -H "Origin: $H" -H "X-Demo-Session: $S" -H "X-CSRF-Token: $C" -H 'Content-Type: application/json' -d '{}'   # 503 hosted_demo_disabled

Prefer your own computer?

A click-through package (11 MB zip, public source plus the built console, no keys) runs the same demo locally; the send step is the same recorded replay. It needs Python 3.13 and uv; RUN_FIRST.txt inside has the one command. To check our numbers yourself, run tools/verify_public_numbers.py there: it re-counts the figures on the pages (22 of 22 match).
